# 記事制作と事実確認の手順

## 書く前に

1. 何に答える記事か（読者の悩み）を一文で決める
2. 一次情報を集める：メーカー公式、公的機関、論文。URL と確認日を `sources` に
3. 体験か調査かを分ける：体験は `:::experience`（運営者が本当に体験したことだけ）、調査は `:::research`

## 書くときの決まり

- 結論を先に。ただし断定しすぎない
- 数字はすべて出典つき。出典がない数字は書かない
- 「買わなくていい人」を必ず書く（商品を扱う記事）
- 医療・健康に関わる内容は `medical: true`、診断や治療効果を断定しない
- 比較は公平に：紹介料の有無で順番や評価を変えない
- 煽る言葉（「最強」「絶対」「今すぐ」）を使わない

## 事実確認のチェック（公開前）

- [ ] すべての数字が `sources` のどれかに書かれている
- [ ] 引用は原文のまま（言い換えたら引用符を付けない）
- [ ] 体験していないことを、体験したように書いていない
- [ ] 価格には確認日がある
- [ ] `npm run check` が通る（存在しない slug への埋め込みは検出される）

## サブエージェントへの依頼の型

調べものを並列で頼むときは、次を必ず指示する：「公式の情報源を優先」「値ごとに原文と URL」「見つからなければ not found、推測しない」「第三者の情報は分けて書く」「ファイルを変更しない」。受け取った値は、公開前にメインのエージェントが自分で原文を確かめる。
